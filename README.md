### 📖 Technical Terms

1. **SAML:** Security Assertion Markup language - It is used to exchange login and permission data between and identity provider and a service provider.

2. **LTS:** Long term support - Software security patches and bug fixes that run for 2-5 years

3. **Defense in Depth:** Strategy that uses multiple layers of security controls to protect data, networks, and systems.

4. **Zombie Bots:** Computer or smart device secretly infected with malware that lets an outside hacker control it remotely.

5. **Certificate pinning:** When an application is configured to trust only a specific certificate or public key.

### 🧠 Concepts That Expanded My Knowledge

#### 1. Indicators of Compromise (IOCs)

I learned how different types of indicators help security analysts identify suspicious activity and investigate potential threats.

| Indicator Type | Description | Example |
|---|---|---|
| **Atomic** | Individual, standalone indicators. | IP addresses, domain names |
| **Computed** | Indicators derived through processing or analysis. | File hashes |
| **Behavioral** | Patterns of activity that may indicate malicious behavior. | Repeated authentication attempts followed by unusual account activity |

#### 2. The Five Network Topologies

Understanding network topologies helped me visualize how devices communicate and how network architecture affects security.

- **Star Topology:** Devices connect to a central switch or hub.
- **Bus Topology:** Devices share a single communication backbone.
- **Ring Topology:** Devices form a closed loop, with each device connected to two neighboring devices.
- **Mesh Topology:** Devices have multiple interconnected communication paths.
- **Hybrid Topology:** Combines multiple network topologies to meet organizational requirements.

#### 3. Securing Linux Systems

One of the most valuable technical skills I developed was understanding how to harden Linux systems and reduce their attack surface.

Topics included:

- Configuring SSH security and restricting remote access.
- Implementing password policies and account permissions.
- Configuring host-based firewalls.
- Enabling audit logging and monitoring system activity.
- Reviewing unnecessary services and system configurations.
- Applying security patches and updates.


#### 4. CPU Privilege Rings

I learned how operating systems use CPU privilege levels to separate sensitive system operations from regular user applications.

- **Ring 0 — Kernel Mode:** Highest privilege level, allowing direct access to critical system resources.
- **Ring 1 and Ring 2:** Intermediate privilege levels that are rarely used by modern general-purpose operating systems.
- **Ring 3 — User Mode:** Lowest privilege level, where most applications operate with restricted access.

#### 5. Types of Security Controls

I learned how organizations use different security controls to prevent, detect, and respond to security incidents.

| Control | Purpose | Example |
|---|---|---|
| **Preventive** | Stops or reduces the likelihood of security incidents. | Firewalls, MFA, access restrictions |
| **Detective** | Identifies suspicious activity or security incidents. | SIEM alerts, intrusion detection systems |
| **Corrective** | Addresses security issues and helps restore normal operations. | Malware removal, patching, system restoration |

#### 6. Administrative, Technical, and Physical Controls

I learned how security controls are categorized based on their implementation.

- **Administrative Controls:** Policies, procedures, training, and governance practices that define expected security behavior.
- **Technical Controls:** Security measures implemented through software, hardware, and system configurations.
- **Physical Controls:** Measures that restrict physical access to systems, facilities, and sensitive equipment.

#### 7. Incident Response Lifecycle

Learning the incident response lifecycle helped me understand how security teams systematically investigate, contain, and recover from cybersecurity incidents.

**Preparation → Identification → Containment → Eradication → Recovery → Lessons Learned**

**Preparation**

Establishing incident response plans, tools, procedures, and team responsibilities before an incident occurs.

**Identification and Containment**

Investigating suspicious activity, determining which systems may be compromised, identifying the scope of an incident, and preventing further damage.

**Eradication and Recovery**

Preserving relevant evidence, removing malicious artifacts and attacker access, addressing vulnerabilities, and restoring systems to a secure operational state.

**Lessons Learned**

Reviewing the incident response process, identifying areas for improvement, documenting findings, and updating security procedures.
